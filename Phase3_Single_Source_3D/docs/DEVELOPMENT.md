# Phase 3 ownership and reproducibility

Phase 1/2 source and models are preserved. Their useful concepts carry over: deterministic observation identity, explicit source domain, evaluator/search separation, raw physical cost, invalid-source masks, finite query budgets and explicit incomplete results. Phase 1's uniform-grid teacher preserves candidate order and normalizes only valid support; its `part_e/adaptive.py` separates coarse traces from a final common lattice. Those principles remain relevant, but its 2D XY source grids, boundary encoders, convolutional students and Phase 2 multi-source intensity/slot decomposition are not a ready 3D architecture. Phase 3 does not import or redesign those students.

Module boundaries are small. `data.py` wraps the existing reader with a student whitelist and explicit `TeacherScene`. `coordinates.py` owns XYZ/ZYX conventions. `oracle.py` calls real certified geometry/visibility, source validity and local rerendering. `physics.py` defines probe selection and transparent sampled/full costs. `teacher/octree.py` owns source-space regions and pluggable refinement. There is no placeholder 3D model or fixed candidate grid in the dataset.

Each phase has its own environment. In particular the 2D vendored `rind-dataset` distribution and the canonical 3D dependency have historical package-name overlap with different modules. Do not force them into one shared environment. Phase 3's `uv.lock` and local source entries resolve its reader, generator and canonical geometry; existing root/Phase 1/2 setup scripts stay unchanged.

Reader-only development uses `uv sync --extra dev`; add `train` for PyTorch and `physics` for native geometry. Build the canonical reference with `RIND_PYTHON="$PWD/.venv/bin/python" ../RIND3D_Generator/scripts/build.sh`. The generator has its own standalone build workflow. Required external libraries are not hidden dependencies on adjacent personal checkouts. An actual relocated build has a different scientific identity; preserve original provenance and recertify rather than copying the completed release's success flag.

Run `uv run pytest -q`. Real-data tests need `RIND3D_DATA_ROOT` pointing to the immutable public release; CUDA tests need `RIND_TEST_CUDA=1` and accessible hardware. `examples/real_smoke.py` exercises nine families and all three sizes without private labels. `examples/octree_smoke.py` is the small end-to-end diagnostic. Save results outside dataset directories: the SDK rejects unexpected changes to a sealed snapshot.

The original source snapshot and artifact checksums live in `RIND3D_Generator/provenance/ORIGINAL_SOURCE.json`. Public identity is always RIND3D; internal profile names, status `READY_LITE` and historical manifest names remain unchanged for compatibility. Source count, profiles and geometry coverage are release metadata. License and citation authors are pending, and source redistribution requirements for external dependencies are documented separately. Large data, native binaries, environments, caches, private records and outputs are ignored and must not enter commits.
