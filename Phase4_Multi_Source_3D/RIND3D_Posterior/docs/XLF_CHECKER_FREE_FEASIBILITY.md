# Can XLF retire per-label physical replay?

**Decision. CONDITIONAL yes for a revised execution architecture; OPEN for the current XLF executable.** A proof can be reused for every input. Each run must still establish its own geometric facts, positive mass and numerical error bound. These can be established when a region is first processed and reused by descendants. Repeated independent geometry evaluation is not a premise of the [global theorem](XLF_PROOF_FOUNDATIONS.md).

**COUNTEREXAMPLE — a correct local statement cannot certify an omitted sibling.** In the earlier physical 64³ thick-box case the replayed leaf genuinely reproduced the whole observation; the omitted branches included at least 15/262144 of feasible volume. The replay on `1c2f6e8` and `af10030` accepted a single-cell answer with TV zero despite a true TV of at least 119/120. The new accounting reference deliberately schedules just that narrow corner on a 2³ window of the same world. It returns ABSTAIN at tolerance 1/20, with conservative upper 17179860992/17179860993. This checks the logic of a lost branch without modifying or invoking the XLF solver.

**COUNTEREXAMPLE — a normal floating sum of one does not establish probability normalization.** With three equal positive lower/upper masses 2⁻²⁴, the pinned `label_from_bounds` returns three copies of the nearest binary64 value to 1/3. The reported floating sum is 1.0. Interpreted as exact stored reals they sum to 1−2⁻⁵⁴. The pinned `tv_of_stored` returns half-L1 = 2⁻⁵⁵. This distance calculation is meaningful, but the bytes have not defined a vector on the probability simplex under the literal float-as-probability contract. This is a small numerical defect in the example, not evidence of a large bias in historical data. Either specify exact reader renormalization and include that operation in the proof, or publish exactly normalized dyadic weights. The latter avoids requiring every reader to implement a new normalization rule.

**TESTED ONLY — archived output.** On the existing 214-cell convex-polyhedra fixture `000004_w00_s0`, repacking the archived integer weights into exactly summing binary64 probabilities caused an exactly computed TV change of about **5.85×10⁻¹⁵**. Reading the new bytes gave sum exactly one and the new stream occupied 2,568 bytes. The recorded single run took about 3.7 ms for encoding, decoding and the distance computation; it excludes geometry, search and disk reading. The new file-level accuracy claim is the sum of the encoding change and the archived bound, conditional on that bound. This experiment does not independently re-prove the fixture's original geometry. ## How small can the trusted kernel be?

**PROVEN for a restricted construction; TESTED ONLY as software.** A complete synthetic 64³ observation with a closed room and an internal occluder gives an end-to-end positive control. The physical shell proof confines every feasible source to one output cell; a certified positive-volume box establishes that the posterior exists. The restricted program binds the exact decoded probability 1 and TV bound 0 to the output without any physical replay. The point search is blind to the observation-generation source, but the solver knows the room's construction. This establishes feasibility of the assurance model on one visibility problem. The production labeler still needs general proof primitives for worlds without a certified separating shell. [Complete example and limitations](XLF_CORRECT_BY_CONSTRUCTION.md)

The most economical first migration keeps productive XLF search and its proven fast filters, and moves responsibility for consuming regions, issuing physical decisions, mass accumulation and final publication into explicit interfaces. A stalled scan, random sentinel or heuristic pencil choice can only propose work. A successful universal physical test at first use should return a scoped fact or a verified piece directly to the kernel. Subsequent descendants reuse that fact. A whole-window re-scan is unnecessary when the receiver obligation set is itself maintained by verified coverage transitions. The restricted reference checks the physical predicates during assessment only; snapshot and wire validation perform no physical queries.

An optional way to shrink the geometric kernel is to allow **inscribed rational simplices**. Untrusted geometry proposes four rational vertices. Membership of all four in the true convex source leaf proves containment. The exact absolute 3×3 determinant divided by six gives the credited volume. Require containment in the correct output cell and an IN or OUT proof over that simplex; ensure multiple credited simplices have disjoint interiors, e.g. through distinct verified partition tokens or a verified subdivision. The undiscovered part remains possible by default. This removes the need to trust an entire approximate clipped hull as an exact volume. **CONDITIONAL efficiency:** an extremely thin feasible region or an overwhelmingly large rejected region may require many inner simplices. The design does not require this route for all leaves. The shadow geometry, legally scoped receiver coverage and positive-volume proof cannot be replaced by a ledger alone.

For filters, write the permitted finite input ranges, exact expression, enclosing inequality, and floating execution model together. For each native/JIT build establish rounding mode, absence of invalid contraction/reassociation, handling of subnormal values, and the exact fallback for any unproved case. Tests on rational adversaries distinguish bugs and preserve fixes. A human proof of an ideal expression does not automatically establish that a compiled filter satisfies it. Unknown, internal overflow and a malformed input must have explicit fail-closed behaviour. A fixed-source cache version that omits dependencies is not sufficient as the build identity for a scientific label.

## Assurance choices

| Model | Work on each label | Assurance and residual trust |
|---|---|---|
| A. Independent replay | Reconstruct the partition and repeat physical and volume checks. | Useful for detecting search/inheritance and serialization faults when coverage and output binding are also checked. Shared geometry kernels have common failure modes. The replay executable and its arithmetic still require assurance. |
| B. Verified transitions in the producer | Physical proofs at first use, incremental accounting, final cheap checks of the actual bytes and bound. | Conditional theorem covers arbitrary heuristics. Trusted surface includes canonical input, physical predicates, geometric representation/volume, state ownership and final API. Manual derivation plus tested code is a defensible model **only with explicitly accepted execution assumptions**. No estimated replay-time saving is proof of end-to-end speed. |
| C. Program-level verification of selected primitives | Same evidence as B if the extraction/build corresponds to the proved program. | Most economical targets are integer credit accumulation, canonical sparse decoding, outward conversion and split/settle ownership. Exhaustive finite-state checking or SMT bit-vector checking of a *bounded* primitive can increase assurance; its result covers that model and those bounds. Proving clipping, transcendence-free exact geometry filters and compiled execution remains separate. No proof assistant or verified production binary was used in this study. |

**Effort and costs.** Partition ownership changes are local in concept but cut across every mutating path (ordinary bisection, slab cuts, solid splits, grid emission and recovery). Incremental cost can be O(1) ledger updates per child beyond geometric work, with O(live tokens + sparse credits) storage if closed descendants are retired. Exactly normalized output costs O(m log m) for largest-remainder sorting and O(m) for payload validation over m output entries, apart from integer bit complexity. A certified local frontier can maintain bounds in the existing grid traversal. Broad complement-only OUT indexing and slack for tiny supports are the more uncertain costs. The reference deliberately uses copy-on-write whole maps and a simple OUT list; its scaling is not a production forecast. The expensive assurance work is proving filtered geometry and inheritance under degeneracy. No measured basis yet establishes the ten-times-FastLabel production target for Model B.

## Gate for optional replay

1. Freeze the actual target measure, input decoder, supported geometries, arithmetic/build envelope and serialized label semantics. Reject unsupported configurations.
2. Give each trusted operation a documented precondition, postcondition and failure path. Enforce single-owner tokens, full receiver obligation coverage, atomic credit updates and immutable source identity. Run omitted/duplicate child, stale token, timeout-at-each-transition, empty lower mass and overflow tests against exact references.
3. Discharge native predicate, clipping and volume enclosure obligations for that build, or route uncertified cases to an audited exact path and abstain where necessary. Validate the wire-bound pipeline against exact rational fixtures, including multiple cells and tiny masses. Establish how the actual emitted bytes are tied to the bound.
4. Keep independent replay during qualification and on future changes to the trusted base. Compare completion, abstention, tails and **full** cost on frozen disjoint cases before choosing a production policy. After the preceding guarantees hold, periodic independent audits can catch regressions; their sampling frequency does not enter the deterministic TV theorem.

**OPEN.** There is no proof of equivalence between every current compiled XLF path and these transitions. **PROVEN.** Per-label independent physical replay is not logically necessary under the stated kernel contract. Per-label physical evidence, positive mass and verification of the actual numerical bound remain necessary.
