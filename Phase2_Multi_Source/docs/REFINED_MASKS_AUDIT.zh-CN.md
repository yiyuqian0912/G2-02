# 新版分层学生：第二次代码审核

日期：2026-10-29。对象：`masks_boundary_refined.json` / `BoundaryRefinedDecompositionField`。此报告验证实现与执行链路，不代表完成全量训练或达到90%成功率。

## 核心逻辑

- 学生只读完整局部响应、窗口位置与size。默认关闭几何输入和Phase1定位；教师层掩码、强度、残差、源编号和位置都不是学生前向输入。
- 接口中的`obstacle`为兼容原数据批次而保留。`use_local_obstacle=false`时编码器不读取它，推断可以提供全0占位；训练中的真实障碍掩码只用于损失/评估屏蔽。翻转该张量不改变模型输出的测试已通过。
- 输出是32个对等槽位的单位掩码、强度与存在性；独立sigmoid允许层间重叠。相同源/贡献可有不连通支持，不施加像素排他归属。
- 响应与边界双分支、多尺度记忆、4/2/2注意力分工及三轮共享权重细化均实际接入。细化反馈来自自身预测的正/负重建误差，没有教师残差输入。
- 最终轮做一次Hungarian匹配，辅助轮沿用同一对应关系。分别监督掩码、强度、存在性、层数、总响应和教师顺序残差；仅重建正确不能替代分层正确。
- 有效层强度按观测max归一化再恢复原单位，可大于1；未把有效贡献强制当成单位物理源。
- 既有完整缓存按原样复用；不重渲染、不截断教师层、不修改原标签生成器或其协议哈希。新输出目录与旧实验分开。

## 本次发现并修复

| 问题 | 触发条件和影响 | 修复 |
|---|---|---|
| 辅助轮没有随最终轮补齐缺失槽 | 允许测试容量溢出且启用辅助轮时，最终轮和教师维度对齐，但辅助轮报`misaligned complete layer targets`。默认32槽、全部标签≤32时不触发 | 对所有辅助轮递归补齐“缺失预测”，保留完整教师分母和原重建值，不删除困难标签 |
| 竞争分数精度与预期不符 | 外层bf16 autocast仍会把`matmul(q.float(), k.float())`转回bf16；原先仅转型不能保证FP32计算 | 显式关闭竞争分数/softmax/归一化区域的autocast；值聚合和其他计算仍使用AMP。dtype测试确认分数FP32、值聚合bf16 |
| 评估匹配可被启动配置改动 | 编辑当前JSON的loss权重后，评估可能换用新权重进行层匹配，与报告“沿用训练匹配”不一致 | 从checkpoint读取训练时loss配置，并把实际匹配配置写入指标报告 |
| 纯解耦默认forward仍继承定位参数要求 | 直接调用新模型而未传候选/定位开关时，会沿用完整管线的默认接口 | 新模型默认按是否启用定位决定forward行为。纯解耦可直接`model(response, obstacle_placeholder, window)`，不要求候选池或教师层 |

这四处修复不改变参数张量形状（默认仍为12,325,731参数）或教师标签。FP32竞争修正会带来正常的数值差异；旧版和新版总loss因归一化/辅助项不同，本来就不能直接横比。

## 验证

- 原生窗口8/16/32/64/128，输出尺寸、有限值、零响应门控、掩码重叠、强度尺度等变。
- bf16、FP32和激活检查点的前向/反向，所有参数有有限梯度。
- 每个样本只做一次最终轮匹配，所有辅助轮沿用该匹配。
- 交换槽位查询的编号只交换层输出，不改变总重建或匹配后的损失。
- 只使用最终轮损失时，梯度确实通过较早轮的预测掩码/残差回传。
- 超容量测试保留所有教师层，缺失层仍被计为错误；最终轮和辅助轮均能完整评估。
- 改动评估启动配置的强度匹配权重，不会改变checkpoint对应的正式指标。
- 中断后恢复训练，与不中断训练的最终参数一致（CPU小规模测试容差atol=1e-7、rtol=1e-6）。
- 双进程Gloo使用不同响应/强度样本，核对共享细化权重和梯度累积的参数更新与单进程全局等效更新一致；同时覆盖一个验证rank没有样本的情况。
- 真实RIND数据用默认32槽、256维、4层、3轮模型跑通4训练/2验证/2测试窗口。候选渲染数为0。样本：train=(5,11),(30,3),(36,2),(58,6)；validation=(53,26),(394,11)；test=(117,2),(282,11)。该小样本仅作执行检查，不能用于准确率结论。
- 仓库回归与shell语法检查；打包后重新解压，核对manifest内容哈希和入口执行权限，再运行分层模块检查。

数据/旧实验依赖的部分Phase1测试在不含原始数据的源码包中会跳过；受本地网络沙箱限制的两项Gloo检查另在允许本地回环连接的环境执行。没有本地CUDA/H20，未声称验证NCCL性能、服务器显存峰值或GPU吞吐。

## 使用

继续使用同名`RIND_Phase2_Update.tar.gz`，训练命令不变：

```bash
./run_refined_masks_tmux.sh start all --gpus auto
```

详细路径、恢复与指标命令见 [运行说明](REFINED_MASKS_RUN.zh-CN.md)。是否提升多层准确率，仍要看服务器训练后的层数分层指标与严格整窗成功率。
