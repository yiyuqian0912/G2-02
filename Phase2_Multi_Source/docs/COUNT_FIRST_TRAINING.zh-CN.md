# 层数优先训练设计（待盘点后确定规模）

更新：2026-11-02。用户已选择**先盘点可用量再定规模**。当前默认入口只盘点，详见[复杂窗口盘点](COMPLEX_WINDOW_INVENTORY.zh-CN.md)。以下保留后续计数优先训练的设计与草案参数，尚未启动；不把新增10万当作已确认目标。

## 1. 这次具体增加什么

现有100,000个训练窗口中，R1=60,900、R2=23,548、R3=9,290、R4=3,763、R≥5=2,499。总量不是一万；真正三、四层只有13,053窗。上一轮30/30/30/10有放回采样并未增加独立样本。

训练模板的旧草案为保留100,000窗并新增100,000个R≥3窗口；新增规模待盘点后确定。验证和测试仍各12,500，内容和数据文件不变。

R指最低正残差/BFS教师的有效层数，不是物理源数K。原始数据K为1–4也可能得到更多有效层，因此本轮仍保留32槽容量。

新增窗口来自原冻结训练场景池，可遍历每场景最多256个已有窗口。继续跳过全亮、全暗、无自由像素和无法完整分层的窗口；这些不计入新增目标。只调用现有局部标签算法，**候选光源渲染次数为0**。

去重与覆盖：

- `(scene_id,view_id)`不与旧训练窗或新窗重复；
- 按障碍几何、源配置、窗口坐标组合进一步去重，避免改view ID或复制配置凑样本；
- 默认每个源配置最多新增4窗、每个几何组最多新增16窗，以避免少数场景占满新增集；
- 检查候选几何不属于冻结验证/测试场景池；
- 完成后报告新增配置数、几何组数和按R/size计数。20万窗口不等于20万独立几何。

源参数只供离线去重建立内容身份，不决定BFS传播，不写入学生输入；逐源真值掩码不参与分层决定。

**数量不足时停止并报告缺口，不用重复抽样或低层窗口补足，不发布可训练的最终索引。**“不足”指当前视窗size、遍历上限和几何/配置限额下的不足，不证明整个数据集没有更多可用信息。`complex_availability.json`记录各类拒绝和限额计数，保留已完成标签块。

## 2. 层数优先怎么落实

模型保持12,325,731参数、32槽、256维解码、4层、3轮共享细化，几何输入和Phase1位置训练继续关闭。默认从当前v3的`best.pt`加载已训练权重，新建优化器；不默认使用尚未逐R审核的last权重。

loss仍同时监督mask、强度、存在性、重建、残差和计数。教师每层强度通过`teacher_intensity`参与监督，真实强度不直接喂给学生。暂不更改loss权重，以便区分新增真实复杂数据的作用。

新版启用`loss.stable_count_loss=true`：直接从存在性logits在FP32 log空间计算计数分布，避免sigmoid舍入到0/1及计数概率下溢后截断造成零梯度。前向输出、辅助轮和loss共用同一分布；数学目标与原计数交叉熵一致，不增加参数。旧配置默认保持原数值路径。

极端值检查中，4槽logits均为30、真值为2层时，原实现计数项梯度全0；新版loss约58.208，梯度有限且非零。这是数值诊断，不证明本轮失败主要由此造成，也不是数据集收益结果。

选模从“只看总验证loss”改为：

1. 将自然验证集分为R1、R2、R3、R4、R≥5五组，分别计算存在概率≥0.5后预测数量的准确率；
2. 以这些组的准确率等权平均`count_group_macro`选best（固定验证集中不存在的组不参与）；
3. 相对epoch0，R1准确率与自然验证整体准确率下降均不得超过0.5个百分点；
4. 主分数相同再看整体计数准确率、计数MAE和验证loss。

这避免少数高层组被R1多数淹没，同时保留自然分布整体表现约束。默认数值是本轮明确的开发规则，需要后续实验验证，不保证已最优。

`best.pt`保存按上述规则选择的权重；`loss_best.pt`另存总验证loss最低权重；`last.pt`保留断点。报告分别写`selected_validation_loss`和`best_validation_loss`，避免把“计数最优”误写成“loss最低”。初始权重依然作为epoch0候选，新模型达不到条件时保留它。

每轮保存真实R×预测R混淆矩阵、各R和五组准确率、分组宏平均、计数分布argmax准确率、选择资格和是否成为best。总loss/概率交叉熵继续报告；计数变准不能代替掩码和强度验收。

训练移除上一轮有放回的分组抽样，每轮遍历全部新训练记录并打乱；多卡尺寸尾批可能少量重复补齐，但这些不会记成新增数据。默认lr=1e-5、最多30轮、patience=8、每卡batch32、目标有效全局batch256。

## 4. 参数在哪里改

未来训练模板：`Phase2_Multi_Source/configs/masks_count_first_train_template.json`；下表为原草案，非当前默认盘点配置。

| 字段 | 默认 | 作用 |
|---|---|---|
| `training_expansion.additional_complex_windows` | 100000 | 真正新增并完整分层的复杂窗口数；不是每轮抽样次数 |
| `label_preparation.record_counts.train` | 200000 | 原训练数+新增数；改新增量时同步修改这里 |
| `training_expansion.min_layers` | 3 | 新窗口至少含几层有效贡献 |
| `training_expansion.max_views_per_scene` | 256 | 遍历每个训练场景已有窗口的上限 |
| `training_expansion.max_added_per_configuration` | 4 | 单个源配置最多贡献几个新窗 |
| `training_expansion.max_added_per_geometry` | 16 | 单个障碍几何组最多贡献几个新窗 |
| `training_expansion.workers` | 8 | 局部Numba标签的CPU准备进程数，不是GPU数 |
| `training.model_selection.metric` | count_group_macro | 计数选模主分数；也支持count_accuracy |
| `training.model_selection.max_single_layer_drop` | 0.005 | 相对初始模型R1准确率允许的下降，单位为比例 |
| `training.model_selection.max_overall_drop` | 0.005 | 自然验证整体准确率允许的下降 |

例如只新增50,000个复杂窗，新增数改为50000、训练总数改为150000，并在已经开始准备后换一个新的`output_root`。

当前专用盘点模式会保存所有去重复杂窗口的元数据，并分别报告限额内可选量；不会保存训练数组或自动训练。请使用默认盘点配置，而非把训练模板的数量简单改成`"all"`。

准备步骤读取原始RIND和连续几何，使用轻量多进程局部标签；神经网络训练、计数累计和多卡同步使用GPU。没有把几何拓扑预处理宣称为全GPU，也没有新增昂贵全场位置教师。

## 5. 后续训练依赖与结果位置

后续训练需要保留（当前盘点不需要模型权重）：

- `outputs/masks_boundary_balanced_v3/mask_records.json`及其可解析的`mask_cache`来源链接；
- `outputs/masks_boundary_balanced_v3/models/seed_0/best.pt`；
- `outputs/masks_only_100k/mask_protocol.json`；
- `data/raw/phase2-merged-110k`及其引用组件，用于读取新窗口。

全部完成后的训练/评估只读缓存，可不再读取原始数据；断点标签准备仍需原始数据。旧缓存字节与评估名单不改。

输出：`Phase2_Multi_Source/outputs/masks_count_first_v4/`。

- `complex_expansion_protocol.json`：原索引哈希、标签协议和新增筛选约定；
- `complex_chunks/`：可恢复、校验和保护的局部新标签；
- `complex_availability.json`：请求/实际数量、配置/几何覆盖与不足原因；
- `mask_records.json`：只有足数后发布的完整索引，含新旧样本和按R/size分布；
- `training_distribution.json`：轻量的新旧窗口数、真实新增R分布、配置/几何覆盖；启动时也会打印实际训练R直方图；
- `models/seed_0/training.json`：曲线、混淆矩阵和每轮选择理由；
- `evaluation/`：所选计数模型的完整掩码、强度、重建和严格整窗指标；
- `evaluation/initial_reference/`：同一冻结评估集上的初始权重对照。

后续训练模板不会覆盖v2/v3结果；代码包不包含这些数据、缓存和权重。

## 6. 验收与限制

首先看验证/测试的计数混淆矩阵，R2/R3/R4是否都改善，是否存在系统性少报/多报；同时报告自然窗口等权和场景等权。分组宏平均只是计数开发目标，不把它冒充完整解耦成功。

计数优先模型也必须报告硬掩码IoU、强度相对误差和严格整窗成功；如果只数对了槽但支持掩码错误，不能进入Phase1当成可用分解。90%计数目标和90%严格整窗目标分开判断。

本地只能做小规模执行/多进程/断点检查；可新增的复杂窗规模、H20真实吞吐以及泛化收益均需实际运行后确认。
