# RIND 单源学生模型优化与阶段训练报告

**报告日期：2026-10-22**

**实验：`phase1_100k_multiscale_h20_memmap`**

**状态：训练进行中；以下结果截至 epoch 36/100**

## 1. 实验目标

本轮训练仍然解决 Phase I 形式的单贡献反演问题：给定局部响应、视窗世界
坐标和视窗 size，预测 1024×1024 全场候选源位置上的条件概率分布。多源
视窗先由 Phase II 教师进行残差分层；每个已经验证的二值层再作为一个单源
任务训练同一个学生模型。因此学生学习的是可复用的单贡献定位能力，不直接
回归多源坐标，也不把多层概率预先混成一个监督标签。

当前学生不知道全场障碍物几何。配置中的 `use_obstacle=false` 保持了实际应用
所需的几何未知设定；模型只能从响应形状、局部坐标和视窗位置推断可能的全场
源位置。

## 2. 实际训练数据

| 项目 | 数量 | 用途 |
|---|---:|---|
| Phase I 单源训练记录 | 37,072 | 100k 场景发布包中经过非恒定视窗筛选的单源监督 |
| Phase II 残差层记录 | 43,271 | 从多源响应中剥离并通过物理检查的单贡献层 |
| 训练记录合计 | 80,343 | 两类记录共同训练同一个单源学生 |
| 验证记录 | 4,530 | 保持为独立单源场景，不追加 Phase II 层 |
| 测试记录 | 4,714 | 训练与选模阶段不读取 |

数据按 `scene_id` 使用固定清单划分，训练、验证和测试的几何场景互斥。视窗
包含 16、32、64、128 四种 size。教师候选 spacing 为 16，因此全场共有
64×64=4,096 个候选位置。

训练集合比验证集合更难且分布不同：训练集合额外包含 43,271 个 Phase II
残差层，而验证集合保持纯单源。这是当前训练 CE 高于验证 CE 的主要可能原因，
不能直接把该差值解释为数据泄漏或传统意义上的异常过拟合。

## 3. 模型结构优化

当前模型为 `multiscale_boundary` 条件能量模型，共 **20,030,020 个可训练
参数**，隐藏维度 384，候选坐标使用 6 级 Fourier 特征。

### 3.1 多尺度边界编码

模型从响应中显式计算水平方向梯度、垂直方向梯度，以及原尺度、2 倍降采样、
4 倍降采样下的边界强度。边界计算在视窗边缘使用复制填充，避免把局部裁剪
边框错误地当成物理阴影边界。

编码器随后分成三个语义分支：

1. **边界分支**保留较高空间分辨率，学习阴影边界的位置和方向；
2. **区域分支**编码大面积亮区、暗区及其内部结构；
3. **全局分支**进一步汇总整个局部视窗的上下文。

这使模型不必依赖同一组卷积特征同时承担边界定位、区域识别和全局概括。

### 3.2 八个注意力头的显式分工

八个注意力头不再读取同一个无区分的 token 集合：

- 4 个头读取边界 token；
- 2 个头读取响应区域 token；
- 2 个头读取全局上下文 token。

模型另外学习三个分支的门控权重，再将边界、区域和全局信息融合。该设计使
多头注意力具有明确任务，而不是仅依靠训练自行产生不稳定的头分工。

### 3.3 候选与观察像素的相对几何

每个候选位置除绝对 Fourier 坐标外，还显式编码：

- 候选相对视窗中心的二维位移；
- 候选到视窗左、右、上、下四条边的归一化距离；
- 候选位置与观察 token 世界坐标之间的二维旋转位置编码。

因此注意力分数能够直接表达“某个候选源相对于当前阴影边界位于什么方向、
距离多远”，而不需要仅从绝对坐标中间接学习这些关系。

### 3.4 条件能量输出

模型对每个候选位置输出能量 `E(O,s)`，再在 4,096 个候选上计算
`softmax(-E)`。训练目标是教师概率与学生概率之间的交叉熵。它保留多峰和
连续可行区域，不把具有歧义的局部观察压缩成单点坐标。

## 4. 教师监督优化

Phase I 物理教师使用已知场景几何逐候选重渲染，并根据响应一致性生成归一化
概率场。Phase II 不再训练一个独立的多源学生；它把完成物理验证的残差层转换
成与 Phase I 相同的单源接口，再追加到训练集合。

这带来两个作用：

- 学生能够接触真实多源观测分解后产生的、更复杂的单贡献形状；
- 验证和测试仍保留独立单源场景，可单独衡量基础反演能力是否改善。

只追加完成分层并通过物理代价阈值的记录。恒亮、恒暗、层掩码不可实现或物理
代价过高的样本不会作为正确答案进入学生训练。

## 5. 训练系统优化

### 5.1 八卡 DDP

旧的单进程 `DataParallel` 已改为一张 GPU 一个进程的
`DistributedDataParallel`。每个进程只维护本卡模型和局部数据，梯度由 NCCL
同步，只有 rank 0 写 checkpoint。这移除了旧的单进程多卡线程路径，并确保
八张 H20 都执行实际模型计算；`SIGFPE` 最终由下一节的稳定 attention 路径
解决。

### 5.2 稳定注意力实现

目标服务器的 PyTorch 2.4 fused scaled-dot-product attention backward 曾触发
原生 `SIGFPE`。当前实现使用数学等价的分块 FP32
`matmul → softmax → matmul`：

- 候选按块计算，限制中间注意力矩阵显存；
- softmax 使用 FP32；
- 保留完整 autograd 梯度；
- 单元测试验证其输出与 PyTorch 参考 SDPA 一致，并验证三组输入均能得到有限
  梯度。

### 5.3 Micro-batch 与梯度累计

FP32 安全路径在每卡 96 条、特别是 128×128 视窗上超过 96 GB 显存。当前
训练采用：

| 参数 | 数值 |
|---|---:|
| GPU 数量 | 8 |
| 全局 micro-batch | 128 |
| 每卡 micro-batch | 约 16 |
| 梯度累计 | 6 次 |
| 每次参数更新的等效 batch | 约 768 |

这样降低了瞬时显存，同时基本保持原实验一次参数更新所覆盖的样本规模。测试已
验证：在等大小 micro-batch 条件下，累计梯度更新与一次大 batch 更新一致。

### 5.4 其余稳定性与吞吐设置

- FP32/TF32 计算；
- 普通 AdamW，关闭 fused optimizer；
- 关闭 cuDNN benchmark，避免不同视窗 size 切换不稳定内核；
- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`，减轻显存碎片；
- 按视窗 size 和候选数分桶，保证同一 batch 可直接堆叠；
- memmap 教师记录按 batch 延迟读取；
- 对只读 NumPy memmap 显式复制后再转换为 Torch tensor，消除未定义写行为；
- 首个训练 batch 对数据加载、前向、反向和优化器步骤分别同步并记录；
- `best.pt` 按最低验证交叉熵保存，`last.pt` 用于精确续训。

## 6. Epoch 36 阶段结果

4,096 个候选上的均匀预测交叉熵为：

`CE_uniform = log(4096) = 8.317766`。

| 指标 | CE | 相对均匀基线降低 | `exp(CE)` | 相对均匀分布的集中倍数 |
|---|---:|---:|---:|---:|
| Epoch 36 训练 | 7.70909 | 7.32% | 2,229 | 1.84× |
| Epoch 36 验证 | 7.42805 | 10.70% | 1,683 | 2.43× |
| 历史最佳验证 | **7.34350** | **11.71%** | **1,546** | **2.65×** |

这里的 `exp(CE)` 是交叉熵对应的等效困惑度，用于比较概率场集中程度，不等于
模型硬选择了相应数量的候选点。

结果说明学生已经显著优于均匀分布。历史最佳验证 CE 比均匀基线低 0.97427
nat；换一种解释，教师真实分布下学生分配的平均概率密度，相对均匀预测提高了
约 2.65 倍。

epoch 36 的验证 CE 为 7.42805，比历史最佳值高 0.08455。这说明当前 checkpoint
并非最佳 checkpoint，但属于正常的后期波动；选模应继续使用 `best.pt`，不应
用 epoch 36 的 `last.pt` 替代。训练代码会依据验证集和 patience 自动停止。

## 7. 当前结论与限制

当前结果支持以下结论：

1. 扩展模型能够从局部响应中学习非均匀、具有几何结构的全场位置分布；
2. 多尺度边界、相对几何和明确的注意力分工在 80,343 条混合训练记录上可以
   稳定优化；
3. 八卡 DDP、稳定 attention 和 micro-batch 累计已经解决此前的原生崩溃与
   显存溢出；
4. 历史最佳验证结果明显优于随机均匀基线。

本报告尚不能声明最终测试性能。训练结束后必须加载 `best.pt`，在从未用于选模
的 4,714 条测试记录上计算完整指标。交叉熵也不能单独说明概率场几何形状是否
正确，最终评价还应包括 forward KL、information recovery、Dice@90、
precision/recall@90、invalid-candidate mass、真实源距离和 Recall@32，并结合
概率场可视化检查边界形貌。
