# RIND Phase I —— 项目职责与交付目标

[English README](README.md) | 中文说明

本项目根据**局部响应和观察窗口的位置，推断源可能位于哪里**。输出是源位置的可能性分布；当观测存在歧义时，应保留多个合理解。

这份 README 说明每位组员**负责哪个文件夹、每个文件要做什么、最终需要交付什么结果**。数学定义和方法细节见 [docs/method.md](docs/method.md)，模块之间的数据约定见 [docs/interfaces.md](docs/interfaces.md)；这两份补充文档目前为英文。

## 1. 研究范围与当前状态

| 项目 | 已确定的范围 |
|---|---|
| 数据集 | 新生成场景，每个场景恰好包含一个源 |
| 源强度 | 整个数据集使用固定强度，具体数值待定 |
| 场景空间 | 1024 × 1024 的连续二维坐标区域 |
| 观察窗口 | 含源区域继续四等分，无源区域停止分割；达到 16 × 16 后仍含源的叶节点不作为观测 |
| 学生模型输入 | 局部响应，以及窗口的位置与大小 `(x, y, side)` |
| 模型输出 | 候选源位置的兼容性评分与概率分布 |
| 数据划分 | 按 `scene_id` 划分训练集、验证集和测试集，场景互不重叠 |
| 任务分配 | 组员在第 6 节自行认领 |
| 首轮检查 | 2026 年 10 月 1 日，周四 |
| 可用算力 | 待定 |

**当前状态：**项目中已有说明文档、初步配置和 Python 包目录骨架。研究模块与运行脚本尚待编写；当前文件夹中尚未找到原始 RIND 生成器和数据。

**下文使用三种文件状态：**

- **已有**：仓库中已经存在。存在 `__init__.py` 不代表模块功能已经完成。
- **待创建**：计划由对应负责人创建的文件。
- **运行生成**：完成某一阶段后产生的数据或结果，不是需要手写的代码文件。

周四检查的是第一轮可验证成果，不要求届时完成全部最终实验。

## 2. 各项工作如何衔接

```text
新生成单源场景
        ↓
无源四分树观察窗口 + 按场景划分的数据集
        ↓
候选源位置
        ↓
RIND 重渲染 + 物理兼容性评价
        ↓
教师分布
        ↓
学生模型训练
        ↓
预测源位置分布 + 评估报告
```

| 阶段 | 负责目录 | 主要产出 | 交给谁 |
|---|---|---|---|
| 准备观测数据 | `src/rind_phase1/data/` | 合法观测、窗口元数据、所属数据集划分 | 物理、采样及训练负责人 |
| 确定待评价的位置 | `src/rind_phase1/sampling/` | 候选位置及其有效范围说明 | 物理及训练负责人 |
| 判断物理解释是否成立 | `src/rind_phase1/physics/` | 重渲染响应与候选物理代价 | 教师目标负责人 |
| 定义学生模型 | `src/rind_phase1/models/` | 能够对候选位置评分的模型 | 训练负责人 |
| 训练学生模型 | `src/rind_phase1/training/` | 教师目标、训练后的模型及运行记录 | 评估负责人 |
| 判断研究结果 | `src/rind_phase1/evaluation/` | 指标、图像、对比结果与失败案例 | 全体组员 |

## 4. 核心研究目录：每个文件要达到什么目标

本节列出的 `.py` 文件均为**待创建**，已有的 `__init__.py` 包标记文件除外。以下文件划分用于明确初始职责；如需调整，应与受影响的负责人共同确认。

### 4.1 `src/rind_phase1/data/` —— 准备研究数据集

**目录职责：**提供新的单源数据集，使观察窗口符合约定的四分树规则，并保证不同数据集之间不存在场景重叠。

| 待创建文件 | 需要做什么 | 预期产出与完成目标 |
|---|---|---|
| `generation.py` | 组织原始 RIND 生成器创建新的单源场景 | 得到新数据集，记录生成设置；每个场景恰好一个源，所有源使用约定的固定强度 |
| `quadtree.py` | 提供并检查符合分割规则的无源窗口 | 窗口位置和大小正确，不包含源；最小尺寸下仍含源的叶节点被排除 |
| `splits.py` | 将完整场景分配到训练集、验证集或测试集 | 保存三组互不重叠的场景 ID 名单 |
| `dataset.py` | 向后续模块统一提供观测与元数据 | 每个样本都有响应、窗口信息和可追溯的场景/窗口编号，并支持不同窗口大小 |

**需要交付：**数据集位置、划分文件、按窗口大小统计的样本数量，以及若干可检查的观测示例。按当前规则，一个单源场景应产生 18 个无源窗口。如果 RIND 已提供正确窗口，应直接使用并验证，保持数据定义一致。

### 4.2 `src/rind_phase1/sampling/` —— 确定需要考虑的源位置

**目录职责：**确定哪些源位置假设需要被评价，并明确候选集合代表的空间范围。

| 待创建文件 | 需要做什么 | 预期产出与完成目标 |
|---|---|---|
| `candidates.py` | 为初始基线提供均匀分布的候选位置 | 得到可复现的世界坐标候选集合，教师和学生可以共用 |
| `support.py` | 明确由场景边界、窗口选择规则及教师可见的场景几何带来的候选限制 | 给出标注清楚的候选有效性信息；明确哪些限制需要隐藏几何，避免在声称不使用几何的预测中隐含使用它 |
| `adaptive.py` | 为后续实验提出更集中于合理区域的候选集合 | 减少物理评价次数，同时测量合理区域是否被保留，并记录候选对应的空间权重 |

**需要交付：**候选坐标、有效性信息及必要的空间权重。首轮优先完成均匀采样基线，自适应搜索作为后续扩展。RIND 已有的等价参数候选不能代替对不同源位置的搜索。

### 4.3 `src/rind_phase1/physics/` —— 判断候选源能否解释观测

**目录职责：**利用已知场景和 RIND 物理过程，评价不同候选源位置。

| 待创建文件 | 需要做什么 | 预期产出与完成目标 |
|---|---|---|
| `renderer.py` | 获得指定候选源在原场景中产生的局部响应 | 使用真实源能够重现已保存观测；其他候选也能产生可比较的响应 |
| `boundaries.py` | 识别真实响应与候选响应中的有效边界 | 提供含义一致的边界信息，并明确没有边界时的处理结果 |
| `response_cost.py` | 衡量候选响应与真实响应的差异，可提高真实边界附近的重要性 | 每个候选对应一个可解释的响应一致性代价 |
| `edge_cost.py` | 衡量真实边界与候选边界之间的空间差异 | 提供可选的边界几何代价，并明确边界缺失或为空时的结果 |
| `cost.py` | 汇总用于评价候选的物理代价 | 每个候选对应一个定义一致的最终代价，并区分仅响应项与加入边界项两种设置 |

**需要交付：**重渲染验证结果、候选物理代价，以及解释得好和解释得差的例子。本目录负责物理评价；学生训练由训练模块负责。首轮基线只使用响应代价。

### 4.4 `src/rind_phase1/models/` —— 定义对源位置评分的学生模型

**目录职责：**提供一个根据局部响应和窗口信息判断候选源位置的模型，预测时无需逐候选重渲染。

| 待创建文件 | 需要做什么 | 预期产出与完成目标 |
|---|---|---|
| `observation_encoder.py` | 表示局部响应及其所在位置和空间范围 | 为各类窗口大小提供可用于候选判断的观测表示 |
| `coordinate_features.py` | 表示候选位置，提供原始坐标和 Fourier 特征两种选项 | 支持在一致实验条件下比较两种坐标表示 |
| `energy_model.py` | 综合观测与候选信息，给出兼容性评分 | 每个候选获得一个评分；越兼容的位置能量越低 |
| `predict.py` | 将指定候选集合上的模型评分转为源位置分布 | 输出概率图，同时保留对应坐标与有效候选范围 |

**需要交付：**可调用的模型，以及不同大小观测对应的候选评分示例。真实源坐标、完整场景几何、障碍物掩码和完整四分树都不作为学生输入。

### 4.5 `src/rind_phase1/training/` —— 将物理评价转为学生能力

**目录职责：**从物理代价构造训练监督，并训练学生模型逼近教师分布。

| 待创建文件 | 需要做什么 | 预期产出与完成目标 |
|---|---|---|
| `teacher_targets.py` | 将候选物理代价转为保留多个兼容解的分布 | 保存教师目标及其对应候选坐标、有效范围、权重与来源记录 |
| `objective.py` | 衡量教师分布与学生分布的差异 | 在相同候选位置和一致概率定义下比较两者，形成训练目标 |
| `trainer.py` | 组织训练和验证，保存运行进度 | 产生模型检查点与训练记录，能够判断学生是否在学习教师目标 |

**文件归属：**T3 负责 `teacher_targets.py`；T6 负责 `objective.py` 和 `trainer.py`。

**需要交付：**教师监督文件、训练后的模型、对应设置和验证记录。先完成小规模样本上的学习验证，再扩大实验规模。

### 4.6 `src/rind_phase1/evaluation/` —— 判断模型学到了什么

**目录职责：**评价分布质量、多解与不确定性的保留、物理一致性、泛化能力及计算成本。

| 待创建文件 | 需要做什么 | 预期产出与完成目标 |
|---|---|---|
| `metrics.py` | 量化学生与教师的一致程度，以及预测的物理兼容性 | 在明确且共同的候选范围上，提供可比较的逐样本指标和汇总指标 |
| `visualize.py` | 同时展示观测、教师分布与学生分布 | 图像能够揭示合理区域、遗漏的解区域和过度集中的预测 |
| `ablations.py` | 在统一评估条件下比较方法组件 | 判断边界代价、Fourier 特征、自适应搜索是否有增益，以及响应相对于仅窗口信息增加了多少价值 |
| `report.py` | 汇总未见场景结果、不同窗口大小的表现、耗时及失败案例 | 形成可审阅的报告，每项结论能对应到结果和实验设置 |

**需要交付：**指标、对比图和简明的结果报告。仅报告坐标误差不够；存在其他物理兼容位置时，模型应保留相应可能性。

## 7. Phase I 的整体完成标准

当团队可以将一个未参与训练的观测，完整地经过已验证的物理教师、训练后的学生和有记录的评估流程，才形成完整的 Phase I 成果。最终证据需要说明：是否恢复了合理的源位置区域及其不确定性；结果如何随窗口大小和未见场景变化；哪些可选组件带来了可测量的收益。

扩大实验前，需要确定原始 RIND 项目位置、固定强度数值、场景数量、数据划分比例和可用算力。科学参数与评价阈值应写入公共配置和方法说明，由团队形成明确约定。
