# Questions and Understanding of Cross-Event Inversion for Boundary Refinement

My current understanding is that the **forward model** is used to learn a latent event representation, while the **inverse model** uses this representation to generate candidate solutions. The Ray Engine then provides independent physical feedback based on these candidate solutions, and this feedback is used to update and refine the latent event representation.

My main question is:

> **Why can the candidate solutions generated by the inverse model provide more valuable information than predictions made directly from the latent event representation, when both can be queried against the Ray Engine?**

## 0. My Current Understanding of the Overall Inverse Workflow

Based on the proposal, my current understanding is that the forward model first learns an event representation:

$$
g_\theta(S, q, u)
$$

where:

- $S$: structure
- $q$: query location
- $u$: light source / driving variable
- $g_\theta$: learned event function

For a simple example, suppose the true visibility boundary is at $45^\circ$:

$$
V(u) =
\begin{cases}
0, & u < 45^\circ \\
1, & u \geq 45^\circ
\end{cases}
$$

Ideally:

$$
g_\theta(u) = 0 \quad \Rightarrow \quad u = 45^\circ
$$

Therefore, the basic relationship in the forward model can be understood as:

$$
u \rightarrow g_\theta \rightarrow V
$$

In other words, given a value of $u$, the forward model predicts the corresponding visibility, with $g_\theta = 0$ representing the event boundary.

### My Understanding of the Inverse Model

The inverse direction is the opposite of the forward direction. Instead of giving $u$ and predicting $V$, the inverse model takes an observed visibility $V_{\text{obs}}$ and searches for values of $u$ that could produce this observation.

Therefore, the inverse model is effectively searching for a feasible set:

$$
F = \{u : d(F(S, q, u), V_{\text{obs}}) \leq \epsilon\}
$$

For example, if:

$$
V_{\text{obs}} = 1
$$

the inverse model might find:

$$
F = [45^\circ, 90^\circ]
$$

Then, the boundary of the feasible set,

$$
\partial F = 45^\circ
$$

corresponds to the event boundary.

So my understanding is:

$$
V_{\text{obs}}
\rightarrow
\text{search over } u
\rightarrow
\text{feasible set } F
\rightarrow
\text{boundary } \partial F
$$

Therefore, the inverse model does not directly read the boundary from $V$. Instead, it determines the feasible region and its boundary indirectly by searching for values of $u$ that are consistent with the observation.

## 1. First Question: If the Event Representation Is Not Reliable, Why Should the Inverse Result Be More Correct?

If the event representation (latent-space information) itself is not sufficiently reliable, and the inverse model generates candidates based on this event representation, why should we believe that the inverse model will produce results that are **more correct** or that can improve boundary accuracy?

Suppose the true boundary is $45^\circ$, but the forward model incorrectly learns the boundary as $43^\circ$:

$$
g_\theta \neq \text{physical truth}
$$

For example:

$$
g_\theta(u) = u - 43^\circ
$$

Then, based on $g_\theta$, the inverse model would consider:

$$
u > 43^\circ \Rightarrow V = 1
$$

Therefore:

$$
\text{wrong } g_\theta
\rightarrow
\text{potentially wrong inverse result}
$$

This leads to my first question:

> **If the forward and inverse models use the same learned event representation, why should we expect the inverse model to produce results that are more correct than the forward model?**

The inversion process itself does not seem to guarantee that the result will be closer to the ground truth.

## 2. Second Question: Why Is an Inverse Prediction More Worth Querying?

Compared with directly making predictions using the event representation, if the inverse model produces a different result, why is that result more valuable or more worth querying with the independent Ray Engine?

Suppose:

- **True boundary:** $45^\circ$
- **Forward prediction based on latent information:** $43^\circ$
- **Inverse prediction based on latent information:** $44^\circ$

In hindsight, $44^\circ$ is indeed closer to the true boundary than $43^\circ$. However, before querying the Ray Engine, we do not know this.

The inverse model could also produce $42^\circ$ or $47^\circ$, which may be less accurate.

Therefore, my second question is:

> **If the inverse model produces a different prediction, before physical validation, why should we believe that this prediction is better or more worth querying?**

In other words:

$$
\text{inverse prediction}
\neq
\text{guaranteed better query point}
$$

unless the inverse model has some additional criterion or mechanism that provides evidence that its candidate is more informative.

Otherwise, the fact that a candidate is generated by the inverse model alone does not establish that it is more valuable to query than a forward prediction.

## 3. Third Question: Where Does the Additional Information for Improving Accuracy Come From?

Where exactly does the information that allows the inverse model to improve boundary accuracy come from?

If the inverse model's inputs are primarily $V_{\text{obs}}$ and $g_\theta$, and $g_\theta$ may not be able to effectively distinguish the true boundary, then:

$$
V_{\text{obs}} + g_\theta
$$

does not seem to contain the information about **where the true boundary actually is**.

This leads to another question:

> **Where does the inverse model obtain the additional information that allows the boundary prediction to become more accurate?**

If the additional information comes from the Ray Engine, then the Ray Engine is what provides the new information, rather than the inverse model itself.

Following the workflow described in the proposal:

$$
g_\theta
\rightarrow
\text{inverse}
\rightarrow
u_{\text{candidate}}
\rightarrow
\text{Ray Engine}
\rightarrow
\text{physical feedback}
$$

For example, suppose the inverse model produces:

$$
u_{\text{candidate}} = 44^\circ
$$

The Ray Engine then computes the physical result:

$$
V_{\text{Ray}}(44^\circ)
$$

If:

$$
V_{\text{Ray}}(44^\circ) \neq V_{\text{obs}}
$$

then the system obtains new information.

From this perspective, **the Ray Engine provides the new physical information**, while the inverse model is more like a mechanism for deciding which query points to test.

This raises a more specific question:

> **Can the inverse model select Ray Engine query points more effectively than other query strategies?**

## 4. Direct Comparison: Forward + Active Boundary Refinement

If the forward model predicts the boundary to be at $43^\circ$, we could simply perform active querying around the predicted boundary:

$$
43^\circ \rightarrow 44^\circ \rightarrow 45^\circ
$$

The Ray Engine can identify the true boundary through these targeted queries, and the resulting physical feedback can then be used to update $g_\theta$.

The workflow would be:

$$
\text{Forward}
\rightarrow
\text{predicted boundary}
\rightarrow
\text{targeted Ray Engine queries}
\rightarrow
\text{refine } g_\theta
$$

The inverse-guided workflow proposed in the project is:

$$
\text{Forward / } g_\theta
\rightarrow
\text{Inverse}
\rightarrow
\text{candidate } u
\rightarrow
\text{Ray Engine}
\rightarrow
\text{refine } g_\theta
$$

This leads to the following question:

> **Why do we necessarily need the inverse model?**

More precisely:

> **What additional value does inverse-guided refinement provide compared with directly performing active refinement around the boundary predicted by the forward model?**

## 5. If the Inverse Model Has an Additional Mechanism, Why Can It Not Be Used by the Forward Model?

Suppose the inverse model uses some additional information or mechanism that allows it to locate the boundary more accurately.

This naturally raises another question:

> **If some additional information or mechanism can make the inverse model more accurate at predicting the boundary, why can the same information or mechanism not be used directly to improve the forward model?**

Unless the inverse model has some structural advantage that the forward model cannot exploit, it is unclear why this information needs to be introduced specifically through the inverse process.

Therefore, I think an important question for the project is not simply whether the inverse model can work, but whether it provides a **unique and demonstrable advantage** over forward prediction combined with active boundary refinement.
