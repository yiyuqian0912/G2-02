# RIND3D — 3D Physical Reasoning Dataset format and reader

`manifest.json` identifies an immutable full, delta or composed snapshot. `release_id` hashes its canonical JSON payload excluding the ID itself. It names the schema, scientific/build configuration, public policy, scene records, split counts, parent and file checksums. `checksums.sha256` covers every included file and the manifest. These are integrity commitments, not externally signed authenticity claims.

`catalog/scenes/SCENE_ID.RECORD_SHA256.json` is one immutable record per READY_LITE scene. The filename validates both the scene ID and exact record bytes. Public `scene_order` is the stable accepted-geometry ordinal; it does not disclose private source-attempt/rejection IDs. Restricted campaigns retain `attempt_id` instead. Catalog creation is append-only: publication does not rewrite earlier records. Ordinary open parses the records once; random lookup is a dictionary operation. Scientific file hashing is explicit, not repeated for the complete corpus on each lookup.

Each `scenes/SCENE_ID/` directory has canonical `geometry.npz`, `response.rindb`, `solid.rindb`, `window_records.bin`, exact count/informativeness indexes, SHA sidecars, `public_scene.json` and a public `scene.seal.json`. The public seal lists only public files. Restricted verification, source coordinates, seed recipes, witness coordinates, candidate pools and process state are never copied into public scene directories.

`public_scene.json` commits the canonical scene/geometry identity, numerical policy and scientific-file hashes. It does not commit the private operational seal, whose journal/timing contents are specific to a production session. Private physical evidence remains associated with the same canonical scene ID in the restricted campaign. Release artifact identity additionally commits the exact public files, documentation and SDK version.

`geometry.npz` contains lossless typed canonical geometry SoA arrays, read with `allow_pickle=False`. Scene/source arrays in an exported geometry must be empty; the exporter checks every key. Geometry remains independent of response resolution. The SDK exposes the array mapping under `structure['arrays']`. It does not require the generator's native geometry engine.

RINDPack v1 stores a fixed header, random-access 64³ brick index and independently compressed brick payloads. Constant bricks use explicit zero/one codecs. Nonconstant packed bits are raw or Zstandard, whichever the existing writer selects. CRC validates decoded bricks; SHA validates the complete file. Header identities and numerical-policy commitments are preserved byte-for-byte. Opaque commitments may depend on hidden sources; no source coordinates or seed recipes are serialized in the public header.

Arrays use Z,Y,X ordering. Packed bytes use little bit order along X. A PackedWindow has `.data`, `.shape`, `.nbytes`, and `.unpack()`. It pads only the last X byte, not logical observations. `RINDPack.read_window(x,y,z,L,packed=True)` supports arbitrary integer, unaligned cubic ROIs. `verify_all()` checks all brick CRCs. `RINDPack(path, verify_file=True)` additionally checks the full SHA sidecar.

`window_records.bin` is little-endian uint16 with shape `(256,4)`, rows `(x,y,z,L)`. Only L=64,128,256 are valid; quotas are 85/85/86. The half-open voxel region is `[origin, origin+L)`. World coordinates divide origins and side by 1024. All default response values are binary. Solid voxels have response zero; FREE shadow is `(~response) & (~solid)`.

`information.rindi` stores a compact hierarchy of lit-FREE/shadow-FREE existence flags. `counts.rindc` is a lossless compressed NumPy container with exact 16³ leaf counts and field identity metadata. `CountIndex.load(path, response, solid)` reconstructs a small coarse prefix structure. Unaligned boundaries are counted from actual stored bits. A dense 1024³ prefix tensor is never needed.

`RINDDataset(root, split='train', window_sizes=None, view='model', response_format='packed')` supports `split=None`, train, val and test. Use `len(data)`, `data[i]`, `data.metadata()`, `data.iter_scenes()`, `data.scene(scene_id)` and the context manager. Response formats are `packed`, `bool` and optional `torch.bool`. Default observation keys are `scene_id`, `window_id`, `window_origin`, `window_size`, `structure`, `observed_response`. No hidden labels enter these inputs.

`scene.roi(origin, side, field='response', packed=True)` reads response or solid ROIs; `scene.window(window_id)` reads a stored response window. `scene.counts(origin,side)` returns `.lit`, `.shadow`, `.solid`, `.free`, `.informative`, `.lit_ratio` and `.ratio_bin`. `data.verify(full=True,crc=True)` performs explicit scientific-file integrity checks. `rind3d-reader verify ROOT` additionally verifies immutable release metadata for snapshots.

`make_dataloader(data,batch_size=4,num_workers=0,seed=0)` groups equal window sizes deterministically. NumPy payloads cross worker boundaries and tensor conversion occurs in the parent. Use a main guard with workers. A returned batch includes packed/bool response tensors, integer origins and window IDs, scene ID lists, size, response format and a list of variable-length geometry structures. Batch order is seed-dependent and is not a scientific scene identity.

`private_oracle()` and `view='candidate_conditioned'` are explicitly refused by public snapshots. On authorized restricted campaigns the reader supplies private true-source and candidate-coordinate access. Physical rerendering still requires the production package; the public SDK cannot reconstruct withheld source evidence. Existing parquet READY datasets can be read with the optional `legacy` extra. Ordinary archive reading has no native extension requirement.
